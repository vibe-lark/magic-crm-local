# 客户演示脚本

建议演示时长 8–12 分钟。演示前运行：

```bash
bun run db:reset
bun run dev
cloudflared tunnel --url http://localhost:3000
```

更新 `APP_BASE_URL` 并重启服务，然后确认 `/demo` 的健康状态为“服务正常”。

## 第一幕：完整 CRM 网页

1. 打开首页，介绍四个核心指标和待跟进列表。
2. 进入客户管理，筛选“意向”阶段并打开“星环零售”详情。
3. 新建一个客户，说明数据写入本机 SQLite，不依赖第三方平台。
4. 打开联系人和跟进记录，展示关联客户及时间线信息。

## 第二幕：权限隔离

1. 使用右上角切换为“陈晓（销售）”。
2. 客户列表只剩陈晓负责的远景科技和星环零售。
3. 切换为“周明（销售）”，列表变成青禾制造和云帆教育。
4. 切回管理员，恢复查看全部客户。

讲解重点：网页和 MCP 都进入相同的 `CrmService`，权限不是只在前端隐藏。

## 第三幕：豆包连接 MCP

1. 打开 `/demo`，复制 HTTPS MCP 地址。
2. 在豆包工作添加自定义 MCP 连接器。
3. 授权页选择“陈晓（销售）”并确认。
4. 说明页面跳回豆包是标准 OAuth 行为：豆包收到授权码后才会交换 Token。

推荐提问：

```text
汇总当前账号能看到的客户和最近 30 天跟进情况。
```

预期：只统计陈晓负责的两个客户。

继续提问：

```text
搜索所有处于意向阶段的客户，并告诉我下一步应该优先跟进谁。
```

预期：返回星环零售以及下次跟进时间。

## 第四幕：MCP 写入后网页同步

在豆包中执行：

```text
为远景科技新增一条电话跟进：已确认下周进行方案评审。
```

回到 CRM 网页点击刷新，进入跟进记录，展示刚写入的数据以及客户跟进摘要更新。这证明网页和 AI 使用的是同一个业务服务与数据库。

## 故障预案

- 隧道失效：重新运行 cloudflared，更新 `.env.local` 并重新注册连接器。
- 授权异常：删除豆包中的连接器并重新发起，不复用旧授权页面。
- 数据被改乱：运行 `bun run db:reset`。
- MCP Session 丢失：让豆包重新连接；本地服务重启后 Session 失效是预期行为。
- 临时无法演示豆包：使用 `/demo` 展示标准端点，再用 MCP Inspector 完成本地调用。
